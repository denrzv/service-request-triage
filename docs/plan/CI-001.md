# CI-001: Implementation plan
Status: PLAN_APPROVED
Workflow path: SMALL_CHANGE

## Overview
Replace `.github/workflows/ci.yml` with a multi-job workflow, add `.github/workflows/codeql.yml` and `.github/dependabot.yml`, and document the jobs in README. Follows the existing pattern in `.github/workflows/ci.yml` (wrapper build, Java 25, `contents: read`).

## Assumptions
- Action SHAs resolved with `gh api repos/<action>/commits/<tag>` on 2026-11-21: checkout v4 `11d5960a326750d5838078e36cf38b85af677262`, setup-java v4 `cf277c60eb25467037889841efdb72551f06f6c3`, codeql-action v3 `d2aacf54c2fbc910db8d7ec338fdb54ea48c692d`, dependency-review-action v4 `2031cfc080254a8a887f58cffee85186f0e49e48`, gitleaks-action v2 `ff98106e4c7b2bc287b24eaf42907196329070c7`.
- Repository is public, so CodeQL and dependency review need no paid features.

## Architecture / Flow
`ci.yml` jobs (parallel): `build` (`./mvnw -B verify`), `gitleaks` (full history), `aidd-validation` (`python3 scripts/check-aidd-pack.py`, then `python3 scripts/validate-workflow.py --ticket "$(cat docs/.active_ticket)"`), `dependency-review` (pull_request only, fails on high severity). `codeql.yml`: init, autobuild-free Java build with `./mvnw -B -DskipTests package`, analyze. `dependabot.yml`: `maven` and `github-actions`, weekly, ignore semver-major for `org.springframework.boot:*` and `org.springframework.ai:*`.

## Contracts
### Inbound contracts
- Endpoint/message/UI event: GitHub `push`, `pull_request` and weekly `schedule` events.
- Request/input: none. Response/output: check results.
- Error behavior: any failing job fails the check.

### Outbound contracts

## Data changes

## Reliability
- Timeout strategy: 20 minutes per job.
- Retry/backoff strategy: none; re-run on demand.
- Duplicate handling: `concurrency` cancels superseded runs for the same ref.
- Ordering assumptions: jobs independent.
- Partial failure behavior: one failing job fails the overall check.

## Security & Privacy
- AuthN/AuthZ: default `permissions: contents: read`; CodeQL adds `security-events: write`; dependency-review adds `pull-requests: read`.
- Input validation: ticket id read from `docs/.active_ticket` and passed quoted.
- Sensitive data/logging: no secrets; gitleaks comments disabled.
- Audit trail: workflow run history.

## Observability
- Logs: GitHub job logs. Metrics/traces/alerts: none beyond check status.

## Testing strategy
- Unit tests: none (no application code).
- Integration/contract tests: the PR's own workflow run must pass; `./mvnw -B verify` still passes locally.
- Regression tests: `scripts/validate-workflow.py --ticket CI-001` and `scripts/check-aidd-pack.py` run locally.
- Manual checks: YAML syntax checked with Python `yaml` if available (else via `actionlint` if installed, else reported as not executed); verify the PR run on GitHub.
