# CI-001: Harden CI
Status: PRD_READY
Workflow path: SMALL_CHANGE

## Context / Problem
The only CI job runs `./mvnw -B verify`. Secret scanning, static analysis, dependency review and the AIDD workflow gates run only locally (`scripts/pre-commit-check.sh`), and GitHub Actions are pinned by mutable major tags. Nothing automatically proposes dependency updates.

## Goals
- Make the main quality and supply-chain checks run on every pull request and on `main`, with no cloud credentials.

## Non-goals
- JaCoCo/coverage gate, SonarCloud, OWASP Dependency-Check, branch protection settings, opt-in live provider smoke job (follow-ups).
- Any application code or dependency change.

## Users & Roles
- Maintainers and agents opening PRs; GitHub Actions runner.

## Acceptance Criteria
- AC1: CI runs jobs `build`, `gitleaks`, `aidd-validation` and (PR only) `dependency-review`; a separate CodeQL workflow analyzes Java on push, PR and weekly schedule.
- AC2: Every third-party action is pinned by full commit SHA with the version in a comment; workflows use least-privilege `permissions` and a `concurrency` group that cancels superseded runs.
- AC3: `.github/dependabot.yml` updates Maven and GitHub Actions weekly and ignores Spring Boot major and Spring AI major updates (ADR-005).
- AC4: `aidd-validation` runs `scripts/check-aidd-pack.py` and `scripts/validate-workflow.py` for the ticket in `docs/.active_ticket`.
- AC5: No secrets are required; README documents the CI jobs and what each checks.

## Non-functional requirements
- Security: least-privilege tokens, SHA-pinned actions, no secret use beyond the automatic `GITHUB_TOKEN`.
- Privacy/data protection: not applicable.
- Reliability: job timeouts set; failures fail the check, never silently pass.
- Performance/scale: jobs run in parallel; Maven cache kept.
- Observability: standard GitHub check results.
- Compatibility: Java 25 build unchanged; repository is public so CodeQL and dependency review are available.

## Data considerations
- Identifiers: none. Sensitive data: none. Retention/lifecycle: none.

## Constraints & Assumptions
- Compact contract; rollback is a revert of the workflow files.
- Assumption: gitleaks-action needs no license for a personal public repository.
- Assumption: `docs/.active_ticket` names a ticket with complete preparation artifacts at merge time.

## Risks
- Gitleaks, CodeQL or dependency-review failing on the first run for environmental reasons; mitigated by checking the PR run before merge.
- `aidd-validation` fails if `docs/.active_ticket` is stale; documented in README.
